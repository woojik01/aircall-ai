# 앱 내 신고 접수 서비스

앱 로그인 없이 HTTPS로 신고를 받고 **비공개 Google 스프레드시트**에 저장합니다. 앱의 API 키·로그인 토큰을 이 서비스에 넣지 않습니다. 신고 작성과 전송은 앱 안에서 끝납니다. HTTP 성공만으로 완료 처리하지 않고 저장 후 반환한 접수 번호를 확인합니다.

## 설정 (배포 계정 소유자)

1. Google Sheets에서 비공개 스프레드시트를 만듭니다. 공유 권한은 운영자에게만 허용합니다.
2. [Apps Script](https://script.google.com/)에서 새 프로젝트를 만들고 `Code.gs`를 붙여 넣습니다.
3. 프로젝트 설정 → 스크립트 속성에 `REPORT_SPREADSHEET_ID`(시트 URL의 `/d/` 뒤 ID), `RETENTION_DAYS`(기본 30)를 추가합니다. 이 값은 앱의 `AIRCALL_REPORT_RETENTION_DAYS`와 같아야 합니다.
4. 편집기에서 `setupReports`를 실행하고 운영자 계정으로 권한을 승인합니다. 매일 실행되는 보관 기간 정리 트리거가 만들어집니다.
5. 배포 → 새 배포 → 웹 앱 → 실행 계정 **나**, 액세스 **모든 사용자**로 설정합니다. Workspace에서 익명 액세스를 막는 경우 해당 환경은 이 방식으로 사용할 수 없습니다.
6. `/exec`로 끝나는 HTTPS 주소를 `AIRCALL_REPORT_ENDPOINT`에 넣습니다. `/dev` 테스트 주소는 배포용이 아닙니다. 코드 수정 후 새 버전으로 기존 배포를 업데이트합니다.
7. 로그아웃한 상태에서 주소를 열어 `ready: true` 및 보관 기간을 확인합니다. 앱에서 응답 포함 여부를 선택해 신고를 보내고, 접수 번호와 시트의 행이 일치하는지 확인합니다.

## 운영

- 비공개 시트에서 신고를 정기적으로 검토하고 문제 유형에 따라 프롬프트·필터·앱을 수정합니다. 이 코드는 사람이 검토한 결과를 자동으로 모델에 학습시키지 않습니다.
- `privacy` 신고의 삭제 요청이나 문의 이메일에 접수 번호가 오면 해당 행을 삭제합니다. 앱 계정이나 기기 식별자로 신고를 추적하지 않습니다.
- 일일 정리 트리거가 보관 기간보다 오래된 행을 삭제하므로 최대 약 하루의 정리 지연이 있습니다. 트리거 실패 알림을 확인하고 시트 복사본·내보내기에도 같은 보관 기준을 적용합니다. 운영 플랫폼 자체 로그/백업 정책은 별도로 확인합니다.
- 동일 ID·동일 내용 재전송은 행을 늘리지 않습니다. 다른 내용으로 같은 ID를 보내면 거부합니다. 사용자 입력을 시트 수식으로 실행하지 않습니다.
- 하루 신규 신고 500개를 넘으면 실패 응답을 반환합니다. 익명 스팸·운영자 계정의 Apps Script/Sheets 할당량 초과 시 접수가 중단될 수 있습니다. 이 경우 앱은 완료 메시지를 표시하지 않습니다. 트래픽이 많아지면 인증정보가 필요 없는 전용 접수 API와 별도의 악용 방어로 교체합니다.
- 공개 URL 자체는 비밀 키가 아닙니다. 시트를 공개하거나 서비스 계정 키를 앱에 포함하지 않습니다.
