# 개발용 종료 진단

알림이 나오지 않을 때는 앱 목록의 **AirCall AI 종료 로그** 아이콘을 직접 연다. 이 화면은 메인 채팅과 알림 전달에 의존하지 않는다. 빌드 번호, 알림 권한·채널 상태, 기록 조회·저장·전송 상태를 표시하며 기록이 없어도 상태 전체를 복사할 수 있다. `알림 권한 허용` 또는 `알림 설정`에서 권한을 확인한 뒤 `알림 테스트`로 전달을 확인하고 `저장된 로그 알림 다시 표시`로 기존 알림의 중복 제한과 무관하게 재전송한다. 알림 테스트는 앱을 종료하거나 기존 종료 기록을 덮어쓰지 않는다.

종료 기록 조회 실패가 저장된 Java 로그의 알림까지 막지 않도록 작업을 분리했다. 첫 조회와 수동 조회는 최근 7일의 기록을 확인하므로 APK 업데이트 전에 발생한 종료도 확인할 수 있다. 시스템이 기록을 남기지 않았거나 오래된 Android에서 네이티브 종료가 발생한 경우에는 로그가 없다는 상태를 명시한다. 이 직접 실행 화면과 알림 테스트도 `debug` 소스에만 포함된다.

- `debug` APK에만 예외 처리기, 종료 기록 저장, 알림 채널과 로그 화면이 포함된다.
- 일반 예외는 클래스와 호출 위치를 저장하고 알림을 시도한다. 기존 Android 예외 처리기로 반드시 넘겨 앱의 실제 종료 동작을 유지한다.
- Android 11 이상은 다음 실행 시 `ApplicationExitInfo`에서 Java/네이티브 충돌, ANR, 메모리 부족, 신호 및 초기화 실패를 확인한다. 네이티브 충돌은 원인 분류와 상태를 기록하며 전체 tombstone은 수집하지 않는다. Android 10 이하는 일반 Java 예외 기록만 지원한다.
- 저장 위치는 앱의 비공개 `noBackupFilesDir`이다. 캐시 삭제로 지워지지 않으며 최신 보고서 하나만 최대 12,000자로 보관한다. 외부 서버로 보내지 않는다.
- 알림 권한이 허용돼야 알림이 나타난다. 권한이 없을 때도 기록은 저장되고 이후 허용하면 알린다. 알림을 누르면 메인 채팅 초기화와 독립적인 화면에서 로그를 확인·복사할 수 있다.
- 예외 메시지, 대화 내용, OAuth/API 토큰은 수집하지 않는다. 클래스·소스 위치·빌드·Android 버전·ABI·시작 단계·시스템 종료 사유만 기록한다. 메모리는 Android의 마지막 표본값으로, 종료 순간의 정확한 값이 아니다.
- `release`는 별도 소스의 빈 구현만 사용한다. `verify_debug_diagnostics.py`가 APK의 dex에서 개발용 진단 문자열의 존재/부재를 확인한다. 실제 테스트 충돌을 유발하는 코드는 테스트 APK에만 있다.

공통 시작 과정은 첫 화면을 먼저 표시하고 구성 객체 초기화를 IO 스레드로 이동한다. 채팅 복원도 IO에서 필터링하며 8 MiB를 넘는 비정상적으로 큰 스냅샷은 읽기 전에 거부한다. 기존 파일을 삭제하거나 덮어쓰지 않고 저장 오류를 표시한다. 이는 시작 지연과 과도한 메모리 할당에 대한 보완이며, 사용자 기기에서 반복 종료한 정확한 원인은 실제 진단 기록으로 확인해야 한다.

에뮬레이터에서 기록 준비 직후 `NavHost`의 화면 이동 구성이 설치되기 전에 `navigate("chat")`가 실행되어 종료되는 경로를 재현했다. 시작 시 화면 이동은 `currentBackStackEntryFlow`의 첫 항목을 기다리고, 구성 설치 전에는 메뉴 이동을 비활성화한다. 이 수정은 개발용·정식용에 공통 반영한다.
