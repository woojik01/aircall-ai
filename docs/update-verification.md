# 삭제 없는 업데이트와 화면 복원 검증

Android CI의 API 35·36 x86_64 에뮬레이터에서 이전 성공 빌드에 설정, 암호화된 API 키·계정 정보·대화, 메모와 모델 파일을 저장한다. 이후 이전 버전의 실제 모델 화면을 렌더링하고 홈으로 보내 프로세스만 종료한다. `adb install -r`로 새 APK를 설치하며 앱을 삭제하거나 저장 데이터를 초기화하지 않는다. 새 앱에서 채팅 또는 모델 화면이 실제로 표시되는지 확인하고 이전 데이터를 다시 읽어 비교한다.

화면 복원은 별도로 검증한다. 업데이트된 앱을 홈으로 보내 프로세스를 종료한 뒤 다시 열고 개발용 실행 기록에 `activity-restored`가 남는지 확인한다. 이 표시는 Android가 실제 `savedInstanceState`를 넘겼을 때만 기록한다. APK 교체 자체가 이전 화면 상태를 제거하는 경우에도 이 별도 검사가 화면 복원 경로를 빠뜨리지 않도록 한다. 이전 모델 화면에서 Activity를 두 번 재생성하는 계측 테스트는 실제 저장 상태 Bundle, 모델 화면 유지, 기존 대화 보존을 검사한다.

기존의 정상 데이터 보존, 과거 설정 타입, 읽을 수 없는 계정 파일, 개발용 종료 로그·알림 검사는 유지한다. 로그와 UI 덤프는 CI에서 만든 테스트 데이터만 포함한다. 정상적인 프로세스 종료나 화면 재생성을 충돌로 분류하지 않는다.

이 검사는 에뮬레이터의 테스트 데이터로 검증한다. 삭제된 실제 개발용 앱의 과거 데이터는 회수할 수 없으며, 여전히 종료되는 구버전 정식 앱의 실제 데이터와 ARM 기기 동작은 여기서 접근하거나 검증할 수 없다. 통과만으로 사용자의 종료 원인을 확정하지 않는다.

## 실제 정식 APK 실행 검사

`Android Signed Runtime Test`는 성공한 `Android Signed Build`의 원본 APK를 내려받아 Android 35·36에서 실행한다. 개인 서명, 정식 패키지, 비디버깅 빌드, APK 해시와 소스 커밋을 확인한다. 새 APK를 다시 빌드하거나 진단·계측 코드를 삽입하지 않는다. 개발용 종료 알림·실행 기록·진단 화면이 원본 APK에서 제외되었는지도 검사한다.

가장 최근의 더 낮은 정식 versionCode를 가진 APK·초안을 찾아 삭제 없는 업데이트를 수행한다. 에뮬레이터에 만든 설정, 메모와 모델 파일을 비교하고, 구버전이 실행되면 구버전의 실제 UI에서 테스트 대화와 가짜 API 키를 저장하여 암호화된 파일과 대화 복호화까지 검사한다. 구버전부터 화면을 표시하지 못하면 그 사실과 시스템 로그를 남기고, 구버전의 일반 파일 보존 및 신버전에서 생성한 암호화 데이터의 APK 재설치 보존을 각각 검사한다. 구버전 암호화 데이터 검사가 수행되지 않았음을 결과의 `encryptedOldData`로 명시한다. AI 서버 호출·OAuth 인증·모델 다운로드는 수행하지 않는다.

정식 모델 화면을 홈으로 보낸 뒤 Android의 STOPPED 상태와 저장 상태를 확인하고 프로세스만 종료한다. 런처로 다시 열어 새 프로세스에서 모델 화면이 복원되는지 세 번 검사한다. 과거 설정 타입과 읽을 수 없는 계정 파일도 검사하며, 마지막에만 에뮬레이터 앱을 삭제하여 새 설치와 비교한다. CI 밖의 휴대폰 데이터는 접근하지 않는다.

정식 서명 빌드가 성공하면 자동 실행된다. 기존 빌드는 수동 `run_id` 입력 또는 `.github/signed-runtime-request.json`의 실행 ID 변경으로 검사할 수 있다. 요청 파일은 정식 APK를 새로 생성하거나 배포하지 않는다. 서명 빌드가 성공해도 별도 실행 검사가 통과했는지 확인해야 한다. x86_64 에뮬레이터의 결과는 사용자의 ARM 휴대폰에서 종료 원인이 해결되었다는 증거가 아니다.
