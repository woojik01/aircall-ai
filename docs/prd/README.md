# AirCall AI — 단계별 PRD

이 문서들은 목표와 완료 기준을 정의합니다. 구현 완료 보고서가 아닙니다. 실제 구현 상태와 제한은 [프로젝트 README](../../README.md)를 참조하세요.

## 프로젝트 목표

AirCall AI는 Android에서 실제 전화 통화에 가까운 자연스러운 음성 대화를 제공하는 로컬 우선 AI 비서 앱이다.

핵심 원칙:
1. Android 우선.
2. 앱 하나로 완결되는 구조를 기본으로 한다.
3. 중앙 백엔드 서버를 사용하지 않는다.
4. 모든 API Key, OAuth 토큰, 외부 서비스 연동 설정은 사용자의 기기 로컬 앱 전용 저장 영역에만 보관한다.
5. 민감한 자격증명은 평문 파일로 저장하지 않고 Android Keystore 기반 암호화를 사용한다.
6. 로컬 AI와 클라우드 AI를 Provider 구조로 분리한다.
7. 화면이 꺼지거나 다른 앱을 사용하는 동안에도 음성 대화를 유지할 수 있어야 한다.
8. 사용자가 대화 중 다른 앱/기능을 함께 사용할 수 있는 멀티태스킹 구조를 만든다.
9. 기능을 한 번에 구현하지 않고 PRD 단계별로 구현·검증한다.
10. 각 단계는 독립적으로 빌드되고 테스트되어야 하며 CI가 통과한 뒤 다음 단계로 넘어간다.

## 문서 순서

- PRD-01: Android 기반 및 앱 아키텍처
- PRD-02: 로컬 데이터 및 보안 자격증명
- PRD-03: 음성 대화 MVP
- PRD-04: AI Provider — 로컬/클라우드 하이브리드
- PRD-05: 백그라운드 통화 및 멀티태스킹
- PRD-06: Tool/연동 시스템
- PRD-07: 통화형 UI 및 사용자 경험
- PRD-08: 성능·보안 강화 및 출시 준비
- PRD-09: 간편 계정 로그인 및 외부 서비스 OAuth 연동

## 구현 규칙

- 명시되지 않은 기능을 임의로 추가하지 않는다.
- 기존 동작을 깨는 대규모 리팩터링은 피한다.
- API Key와 토큰을 소스 코드, Git, BuildConfig, 로그에 넣지 않는다.
- 서버에 사용자 자격증명이나 대화 기록을 저장하지 않는다.
- 외부 서비스 연동은 사용자가 직접 인증하고 로컬에 저장한다.
- 권한은 필요한 시점에 최소 범위로 요청한다.
- 백그라운드 마이크 사용은 Android 정책과 시스템 표시를 준수한다.
- 실패 시 조용히 무시하지 말고 사용자에게 이해 가능한 오류를 표시한다.

## 완료 기준

각 PRD는:
- 요구사항 구현
- 단위/통합 테스트
- Android 빌드 성공
- 가능한 경우 실제 기기 테스트
- CI 성공
- 문서 업데이트

를 모두 완료해야 Done이다.
