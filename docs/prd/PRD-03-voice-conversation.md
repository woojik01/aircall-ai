# PRD-03 — 음성 대화 MVP

## 목표

사용자가 버튼을 누르고 말하면 AI가 자연스러운 짧은 음성으로 응답하고, 응답이 끝나면 다음 발화를 받을 준비를 한다.

## 음성 대화 원칙

음성 모드에서는 일반 채팅과 별도의 응답 정책을 적용한다.

- 실제 대화처럼 짧고 자연스럽게 답한다.
- 기본적으로 한두 문장으로 답한다.
- 사용자의 말을 불필요하게 반복하지 않는다.
- 문어체보다 자연스러운 구어체를 우선한다.
- 목록, 제목, 마크다운, 코드, 표, 인용문을 사용하지 않는다.
- 이모지와 특수 기호를 사용하지 않는다.
- 최종적으로 TTS에 전달하기 전에 앱에서도 출력 정규화를 수행한다.
- 출력 정규화는 모델의 지시를 따르지 않는 경우에도 음성 출력 형식을 보장하는 마지막 방어선이다.
- 대화 기록에는 정규화된 assistant 응답을 저장하여 화면과 TTS가 동일한 내용을 사용한다.

## 대화 흐름

```
Microphone
 → Speech-to-Text
 → Conversation Engine
 → Voice Conversation Policy
 → AI Provider
 → Voice Response Sanitizer
 → Text-to-Speech
 → Speaker
 → 다음 발화 대기
```

Voice Conversation Policy는 요청에만 system instruction으로 삽입하고 일반 대화 기록에는 저장하지 않는다.

## 응답 형식 보장

VoiceResponseSanitizer는 AI 응답에서 다음을 제거한다.

- 이모지
- 이모티콘(`:)`, `;-)` 등)
- 마크다운 기호(`* _ ~ # > [ ] { } |` 등)
- 장식용 기호 및 기타 특수문자
- URL

한글, 영문, 숫자, 공백과 TTS 억양(의문/감탄/쉼)에 필요한 문장부호(`. , ! ? … : ; ' ( ) " -`)만 남긴다.
문장부호만 남고 글자나 숫자가 없으면 짧은 기본 문구를 사용한다.

## 상태

```
IDLE
LISTENING
PROCESSING
SPEAKING
ERROR
```

## 자연스러운 연속 대화

한 턴이 끝나면 다음 턴의 STT를 자동으로 시작한다.

- 사용자가 말하지 않으면 해당 턴을 건너뛴다.
- AI 응답이 끝난 뒤 불필요하게 긴 대기 시간을 두지 않는다.
- TTS 중지는 유지한다.
- 향후 barge-in에서는 사용자가 AI가 말하는 중 발화를 시작하면 TTS를 즉시 중단하고 새 발화를 처리한다.

## 지연시간

각 단계의 latency를 측정한다.

- STT 종료 시각
- AI 응답 완료 시각
- TTS 시작 시각
- TTS 종료 시각

음성 원문이나 API 키는 로그에 기록하지 않는다.

## 완료 조건

- 실제 Android 기기에서 음성 입력 성공
- AI 응답을 음성으로 재생
- 10회 이상 연속 대화
- 음성 응답에 이모지와 특수문자가 없음
- 긴 설명 대신 자연스러운 짧은 응답이 기본값으로 생성됨
- TTS 중단 가능
- 오류 복구 가능
- CI 통과
